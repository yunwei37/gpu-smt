# E1074 executed composition and legacy labels
Allconditions use a shared native library containing retained Cost modules and
new Power modules. The normal-output block omits --diagnostic heavy records;
compiled CPU counters/product metadata hooks remain. It is not a claim of
zero instrumentation overhead or an unmodified stock Lean executable.

*power: IntegerPowerOracle -> PowerOracle -> CostBaseline fallback.
*direct: IntegerCostOracle -> CostOracle -> samefallback.
*native-dual: IntegerCostControl -> CostBaseline with current dual numerical
  executable selected by oracle-highs.
*stock-native(legacyfolder/method label): same compiled native CostBaseline,
  but fast-hybrid selects the retained upstream native numerical executable.
  This is an **adapted compiled Fast/hybrid native control** with common
  invocation-local product proof application reuse, existing Fast selection,
  officialomega and stockMathlibfallback. It is not pristine upstream frontend.

CostBaseline.run uses CostFast.tryFast then the instrumented native linarith
path with CostProducts.extras; failure restores state and stockExtras fallback.
These source modules were already frozen before E1074; no capture was patched
to obtain this clarification. The legacy labels are preserved in raw data.

Whole-system native control and already-our-dualbackend component control remain
different references. The final result must name the measured composition.
Original user1.5criterion is not silently rewritten as1.5overeachnewablation.
If an uninstrumented or complete upstream artifact becomes decision-relevant,
it needs a matched qualified measurement, not relabeling this capture.
