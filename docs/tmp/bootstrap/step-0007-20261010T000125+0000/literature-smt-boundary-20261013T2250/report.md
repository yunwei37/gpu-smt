## Decision

**Feasible as an internal, pinned native frontend integration; unavailable as an exposed unmodified CLI snapshot interface; exact 4.12.5 branch behavior and resource-history fidelity remain unqualified.** Z3 4.12.5 provides a parser return at complete-input EOF that retains the caller-owned native command context, and provides parser reuse with input replacement. Neither needs an inserted solve, scope, renamed symbol or reconstructed assertion list. The maximal literal common declaration/assertion prefix can therefore be processed and retained before its original candidate-specific suffix. This establishes a concrete source mechanism, not native quiescence or measured benefit.

The strongest public CPU alternative includes solver translation into independent contexts, alongside competent incremental warm workers and exact successful-result caching. Translation is stronger than the claim that all logical reuse is necessarily a shared mutable history: its combined-solver implementation explicitly copies mode/history flags. It nevertheless does **not** clone the complete CLI command context, parser, global parameters, AST allocation identity or native resource counter. Equality of full native histories is unsupported; actual complete verification can determine whether these differences matter on this workload. Preserve the ambitious formal/service/SMT/RQ1–4 contract regardless of the outcome.

## Concrete native boundary

[Shell frontend](https://github.com/Z3Prover/z3/blob/a7b564cafe3b96c8a868388bc4b96b319facea44/src/shell/smtlib_frontend.cpp#L157) lines157–191 constructs default cmd_context, installs strategic solver/command families and invokes the parser interactively for stdin. It owns that context until parsing ends; EOF then leads to final reporting and context destruction. The executable offers no externally returned checkpoint handle or general clone command here. Merely withholding stdin can leave a parser blocked, not expose a supported clone API.

[Parser](https://github.com/Z3Prover/z3/blob/a7b564cafe3b96c8a868388bc4b96b319facea44/src/parsers/smt2/smt2parser.cpp#L3171) lines3171–3194 executes commands until EOF and returns; lines3240–3250 provide fresh-stack and retained-parser entrypoints. A fresh stack parser's destructor resets parser stack, not the caller's cmd_context. The retained-parser entrypoint uses reset_input and keeps the parser object. Thus a complete-command prefix represented as a bounded stream can return without a solve/reset/scope, retain context and resume on its untouched suffix. This is an internal source interface, declared in smt2parser.h:28–30, not public libz3 ABI. Resource/output equality after either split needs qualification; parser preservation is a particularly useful control when rebuilding its transient objects could alter allocation order.

[Scanner](https://github.com/Z3Prover/z3/blob/a7b564cafe3b96c8a868388bc4b96b319facea44/src/parsers/smt2/smt2scanner.cpp#L398) reset_input changes stream, interactive flag, EOF/buffer state and reads the next character. It is not a complete parser/CLI process checkpoint. An in-parser boundary hook that retains scanner/parser objects and resumes after completed command execution is another possible source modification; the inspected entrypoint does not export a callback for that purpose. Input lookahead and exact comments/whitespace around the split must be accounted for, including changed error positions. Returning at synthetic EOF is therefore source-feasible but not already behavior-identical by definition.

[Command context](https://github.com/Z3Prover/z3/blob/a7b564cafe3b96c8a868388bc4b96b319facea44/src/cmd_context/cmd_context.cpp#L604) constructor604–622 records manager ownership and installs commands;809–895 creates its manager lazily, with native declarations/plugins/solver retained;2243–2261 shows factory installation can reconstruct solver assertions/scopes when a manager already exists. A faithful native integration must preserve the shell construction order, original options, owned manager, symbol tables, assertions, solver factory and scopes. Initial command-prefix equality is enough to nominate a state, not to prove arbitrary COW safety or supported concurrent mutation. Pre-solve prefixes avoid inherited learned search from preceding candidates but can still involve native allocation/configuration/resource work.

Its solver_from_stream path296–328 creates a parser command context, ignores checks and transfers tracked assertions into the API solver: this is not an untouched full native command execution oracle. Use solver translation as a strong supported independent-CPU alternative with explicit full frontend/protocol glue costs and declared departure from CLI construction; do not replace original multiple checks/model requests with one solver check.

[Combined solver](https://github.com/Z3Prover/z3/blob/a7b564cafe3b96c8a868388bc4b96b319facea44/src/solver/combined_solver.cpp#L128)128–136 translates both child solvers and copies incremental/check-executed/result-selection flags.162–188 switches mode on assertions after a check and push/pop.
