# Experiment012: owned runtime thread completion before native branches

## Research question
RQ2 verbatim: **Does branching from prepared native state preserve verifier responses and requested artifacts while isolating candidates and cancellation?**

Specific uncertainty: can a native runtime adapter that owns and joins both ordinary and dedicated Lean threads, including their finalizers, establish an executable full-snapshot branch boundary with unchanged complete candidate feedback? This tests a new concrete runtime ownership mechanism, not whether another identical manager-shutdown/TID check happens to pass. E009 remains closed with its original counts and raw failures.

Runtime destruction joins only ordinary handles. No existing comparison tracks and joins this second lifetime. An implementation that retains those handles provides a new causal discriminator. It does not prove the actual old source96residue was dedicated; a joined-dedicated count and unchanged old-boundary control must test that. Existing normal controls cannot settle all official candidate streams.

Best alternative is ongoing E008/E011cost characterization, retained without interruption. Their complete costs determine eventual value but cannot supply a safe branch mechanism.
