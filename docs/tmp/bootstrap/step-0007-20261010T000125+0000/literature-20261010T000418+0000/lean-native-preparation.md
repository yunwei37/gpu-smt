## Must-fix — use public native routes rather than reconstructed snapshots

Section: condition implementation. Problem: supplying final source environment, deleting arbitrary child fields, or fabricating a header snapshot does not implement the specified preparation-depth ablation.

Concrete fix: prepare the original complete source once with `Language.Lean.process setup none {inputCtx with}`; retain its real `InitialSnapshot` (= `HeaderParsedSnapshot`). Its `result?` contains `HeaderParsedState.parserState` and `processedSnap : SnapshotTask HeaderProcessedSnapshot`; the latter's `result?` is `HeaderProcessedState`, containing the genuine post-import `cmdState` and `firstCmdSnap : SnapshotTask CommandParsedSnapshot`. Keep these exact original roots after complete finalization.

Full reuse has two public routes. The maximal entire-frontend route is `Language.Lean.process setup (some originalInitialSnapshot)` in the candidate ProcessingContext. It reuses imports and unchanged command results, then forwards genuine old dynamic elaboration snapshots into the changed command; elaborators decide which headers/tactics/body pieces remain reusable. Never force reuse past syntax changes. The equivalent command-front route, useful for a matched header-parsing boundary, is `Language.Lean.processCommands candidateInput candidateHeaderParserState originalHeaderCmdState (some (originalInput, originalFirstCommandSnapshot))`.

Header-only route: freshly call `Parser.parseHeader candidateInput`, check its messages and header compatibility against the original real header, then call `Language.Lean.processCommands candidateInput candidateHeaderParserState originalHeaderCmdState none`. This explicitly public convenience API, Language/Lean.lean:757–769, supplies no old command/elaboration snapshot and rebuilds all commands from the genuine post-import state. It retains imported context, parsed option processing, main-module identity and header diagnostics. No artificial terminal/header snapshot is needed. Collect original header parse/import diagnostics separately, followed by the candidate command tree. A changed or failed header is not admissible for this retained-header condition; route it through ordinary full header processing and record that outcome, rather than reusing a semantically guessed environment.

To avoid unequal parsing accounting, either have both routes parse candidate headers and use the two command-front calls, or charge and document that the full route uses stock incremental header parsing whereas header-only reparses. Native header syntax comparison uses source information and unsetTrailing; import-list equality alone is insufficient. Fresh parserState is needed even for comments/trailing whitespace changes.
