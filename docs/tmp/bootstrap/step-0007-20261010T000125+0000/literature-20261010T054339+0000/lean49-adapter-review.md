## What is genuinely engaged by the adapter

1. **Native same-version full snapshots, not an imitation.** `full` passes the original `IncrementalState` returned by pinned `IO.processCommandsIncrementally`; that API passes its actual previous input context and `initialSnap` into `Language.Lean.processCommands`. Native command parsing, syntax/position guards and elaborator child snapshots decide reuse. The adapter does not replace those guards with a theorem-name or accepted-result cache. `old_snapshot_supplied=true` proves only that a tree was supplied, not that any particular command/header/tactic was reused.
2. **The required initial-state invariant is respected.** Each header root stores the genuine post-import `Command.mkState` and parser boundary. Every candidate receives that same original state. Its predecessor's terminal command state is used only inside the stock previous snapshot, never as the next candidate's initial environment. Native reuse deliberately restores still-valid predecessor prefixes; independent initial state therefore does not mean that no predecessor data are read, or establish general history isolation.
3. **Whole commands reach normal finalization.** The incremental convenience API traverses next-command tasks to the terminal command and reads `finishedSnap.get.cmdState`; `SnapshotTree.getAll` waits on descendant tasks when collecting diagnostics/info trees. `doElab` invokes stock `Elab.Command.elabCommandTopLevel`. Pinned nonrecursive declaration finalization reaches `addDecl`, whose `Environment.addDecl` invokes `addDeclCore`; the adapter initializes imports with trust0 and has no kernel-disable shortcut. This source path is stronger than merely observing closed tactic goals. It does not mean every reused unchanged declaration is kernel-checked anew, nor that a candidate with errors/sorry/axioms is accepted.
4. **Header guards are conservative.** Candidate text must start with the exact declared header; root selection uses exact header equality. The actual parsed import prefix including parser boundary must equal the selected root's bytes. Changes in the declared header select another root, while body/prefix commands beyond imports are processed by the official frontend. There is no theorem-name-based reuse, Unicode masking or assumed equivalence. This can forgo reuse when texts are semantically equivalent, which is a performance limitation rather than an unsafe reuse permission.
5. **Retirement drops adapter references, not the process.** At the declared candidate count, `roots := #[]` discards import-root and previous-snapshot references together. Initializers execute normally, and `processHeader` uses default `leakEnv=false`. However no process restart, cache flush, cancellation or measured memory reclamation occurs. Bounded root references must not be described as bounded resident memory, resource isolation or reclamation of all native/global caches/import machinery.

## Findings and necessary scope corrections

### Header/import diagnostics were initially lost; the inspected correction addresses their preservation separately

`Language.doElab` clears the input `cmdState.messages`. The convenience incremental API reconstructs diagnostics from the **command** snapshot tree because `Language.processCommands` skips the header. Therefore merely placing `processHeader` diagnostics in `root.initial.messages` did not return them. `processHeader` catches import failures and returns an empty environment plus an error; losing that error is materially unsafe for a claim of complete native diagnostics or for an acceptance predicate based solely on the reconstructed command messages.

Root's inspected correction stores the original header/import message list and emits `import_diagnostics` and `complete_diagnostics = importMessages ++ messages`. That fixes the source omission without modifying native elaboration or kernel checking. The producer REPL itself drops the initial header-message prefix in `processCommandsWithInfoTrees`; consequently the producer-compatible `response.messages` and complete diagnostics have deliberately different roles. A matching producer response alone cannot certify that imports succeeded. Acceptance and compatibility analysis must preserve/classify header/import errors separately; a missing-import case remains a required qualification target. The correction has not been empirically tested in this review.

### Diagnostic and sorry compatibility remain unqualified

The same `REPL.Message.of`, `InfoTree.sorries`, `ProofSnapshot.create` and goal rendering are reused. This is good source alignment for rootless producer commands. Numeric proof handles are local and offer no callable proof-state API. However native incremental reporting collects messages in snapshot-tree preorder, while the producer uses its nonincremental frontend accumulation. Native `Language.doElab` also isolates streams and converts elaborator output into information diagnostics (`stderrAsMessages` defaults true); the producer path does not do that. Complete response order/content, output capture and error-position parity must be measured, not inferred from common renderers.

`InfoTree.sorries` detects explicit sorry syntax with corresponding tree information; it is not an all-axiom or sorry-dependency audit. Stock `addDecl` warnings and full error lists remain necessary. A declaration can also be admitted after error recovery; declaration presence or a fingerprint is not an acceptance oracle. The fresh producer uses `ProofSnapshot.create` without an environment override as the adapter does; an env-rooted warm producer may override with its initial environment, so even goal pretty-print identity requires actual comparison rather than source assumption.

### Runtime, witness and error observations must not be overinterpreted

- `elapsed_ns` is an adapter operation interval. It includes import-root creation on first encounter, native checking and witness/response construction; it excludes input-file loading, root retirement before the start timestamp, output JSON compression/printing/flushing, startup and process teardown. It is not end-to-end verification latency or whole-corpus makespan. Timing/reference-retirement boundaries need clear labels or external whole-process measurements for the final RQ3 comparison.
- Local fingerprints include names, levels and expression hashes, not a collision-resistant complete declaration serialization, all environment extensions, statement-integrity audit or semantic equivalence. The unsorted local map list can produce order-dependent comparisons. Treat these as discriminating observations, normalize ordering for comparison if necessary, and keep original native response/status as the main oracle.
- Adapter exceptions are emitted as `adapter_error` and main may still exit0. Per-row adapter errors cannot be counted as proof rejections or omitted by inspecting only process exit. Failures during diagnostic/sorry rendering must remain incomplete/unknown observations with raw output retained.
- Roots are keyed by the supplied header under one pinned dependency context. This is not a service key for multiple projects, imported-module revisions/options or trust policies. Native global state and custom elaborator/initializer side effects are not isolated merely by persistent command states. No arbitrary-candidate security or cancellation guarantee follows.
- The `imports` mode still invokes the same incremental frontend with `old=none`. It is a controlled removal of prior full snapshots while retaining import state, not a claim that the producer's strongest native warm service is incapable of reuse. A full-versus-imports advantage cannot itself establish novelty over the existing native snapshot mechanism.
