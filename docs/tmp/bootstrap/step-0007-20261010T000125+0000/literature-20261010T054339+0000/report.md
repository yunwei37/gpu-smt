### Supported same-version boundaries

`Lean.Elab.IO.processCommandsIncrementally inputCtx parserState commandState old?` is public and returns `IncrementalState`, including the original input context and initial command snapshot. Its own contract requires the same initial state across invocations, usually with changed input. It calls `Language.Lean.processCommands`, waits along the entire command chain, collects diagnostics and InfoTrees from the complete snapshot tree, and returns terminal finished command state. Passing the previous *final* environment as the next initial state would violate this intended reuse contract and pollute independent candidates with prior declarations.

`Language.Lean.processCommands` is the public command-front route that accepts the real post-import Command.State, actual parser state and optional `(oldInputContext, oldCommandParsedSnapshot)`. Complete command snapshots contain syntax, parser state, dynamic elaboration subtree, finished command state and tactic cache. Unchanged commands before the first textual difference reuse finished snapshots; at the first changed command, the old dynamic elaboration snapshot is forwarded into ordinary `elabCommandTopLevel`. Later commands are rebuilt from its resulting state. Import/header processing can be retained separately using the actual same-version header result. The full `Language.Lean.process` route also exists for native header handling; the convenience command route is sufficient to avoid any fabricated snapshots.

Inside `Command.elabMutualDef`, all previous headers plus the current full declaration header are checked with source-range-aware syntax equality. `Term.elabHeaders` restores full native term/meta/core state using `withRestoreOrSaveFull`. If all headers and prior bodies match, changed top-level `by` bodies retain the old tactic snapshot bundle even when whole-body reuse is ruled out. An unchanged complete body may restore its value and saved state. Unsupported body forms, changed modifiers/headers/context, changed preceding commands and range changes invalidate the relevant reuse automatically; do not force reuse by printed theorem type or names.

The tactic sequence implementation already keeps finished/inner/next snapshots. An unchanged tactic restores its saved native state and skips execution; supported inner combinators may reuse children of a changed tactic. Changed separators stop downstream reuse, and unsupported tactic elaborators have incremental context disabled. Ordinary indented/bracketed tactic sequences are registered incremental wrappers. This is conditional native prefix reuse, not arbitrary tactic reuse or proof-graph equivalence.
