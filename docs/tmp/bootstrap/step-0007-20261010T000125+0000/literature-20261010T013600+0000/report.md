No explicit name, prefix, suffix, directory or crate-name override is provided. It closes after writing, passes the actual name to Verus, and unlinks after subprocess completion. Consequently the policy is ephemeral independently allocated filenames, not a stable task filename. Exact historical names and Python-selected temporary directory are not retained here. ## Native phase/order versus saved artifacts

Inference cleans the candidate and may run type-debugging before scoring, then checks safety; a successful safe candidate returns before the usual intermediate save. Saved inference files append safety/score comments. Merge scoring uses current code-pool order, saves score-commented merged candidates, then calls Houdini; selective and allmerged paths can return early. Houdini repeatedly verifies changed code while deleting failed invariants, with no guarantee that every internal input was saved. Refinement evaluates current code, evaluates repaired alternatives, may return on success before save, and includes additional compilation/debug and finer-grained checks. Saved repair files and stage labels therefore are not a complete native call sequence or necessarily the ephemeral native source bytes. These source facts reinforce existing acquisition limits; they do not recover omitted attempts or prove exact historical producer-version correspondence.

Experiment006 copies saved files once to `inputs/candidate_INDEX.rs`, sorts released paths lexicographically, then reuses each copied filename across direct/capture conditions and repeats. It explicitly runs with cwd=verus.parent, one verifier thread and time/time-expanded flags. That is deterministic saved-source replay ordering, not the producer’s adaptive phase order. Repeated identical source evaluated at different publisher call sites would normally receive newly allocated names; repeated experiment006 cells for the SAME index retain one name. Direct/capture paired feedback is therefore internally matched, while original historical context remains unrecovered.
