# Experiment013: public-header preparation for complete parallel Lean verification

RQ3 verbatim: **How does prepared-state branching change end-to-end latency, throughput and memory at equal resources compared with established warm-session reuse?**

Role: decisive implementation/performance comparison for the concrete Lean service mechanism, not a fork microbenchmark. The existing full-parent route first evaluates an actual candidate seed. This implementation instead prepares only the published original task header (imports, options and open commands) into stock command-state/parser snapshots, shares it between independently disposable candidate processes and reuses genuine post-import state across headers. Parent never evaluates a candidate body. Default native task-manager scheduling replaces the previously verified false-timeout one-worker setting. Kernel/frontend/proof checking are the pinned native Lean implementation, with trustLevel0 imports.

## Admission and decision

The largest credible result is a parallel verifier with a useful complete-throughput/private-memory tradeoff against a competent native snapshot pool. The load-bearing uncertainty is whether sharing privately reconstructed preparation saves enough to offset independent-process initialization and COW writes. Native file-backed imports, command snapshots and previous-candidate reuse make the competitor strong; import-only branch experiments and thread-joining preflight do not settle this version. Positive results keep this preparation mechanism for the final service/load evaluation; negative results reject performance benefit for this mechanism/workload; mixed results delimit the resource tradeoff. No result closes all RQ3 or supplies GPU speedup. The strongest alternative next work is residual frontend/kernel profiling for a native/GPU implementation: this direct system performance comparison is now runnable and tests the central service mechanism instead of another correctness-only dependency. Arithmetic profiling showed no convincing whole-verification benefit and does not justify prioritizing an LP port. User instruction “不需要正确性这么纠结” means diagnostic spelling is not a blanket barrier to optimization.
