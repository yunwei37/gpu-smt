## Question and answer

Can a process-owned root retain a completed first *actually arrived* candidate as native old snapshots, then run independent alternative candidates through complete source verification from the original initialization? **Yes, as a supported tool use of this pinned frontend, with the qualifications below.** The reuse object is a completed `IncrementalState`, not a prior candidate's terminal environment and not a goal-only acceptance result. The first seed remains an ordinary charged candidate, including rejection, incompleteness and failures. A subsequent candidate receives its exact source, the original post-import parser/command initialization, and the seed only in the optional old-snapshot argument. Native guards decide which earlier work is usable.

The immutable reuse contract is:

```
S_seed = processCommandsIncrementally(input_seed, parser_initial, command_initial, none)
S_candidate = processCommandsIncrementally(input_candidate, parser_initial, command_initial, some S_seed)
```

Never substitute `S_seed.commandState` for `command_initial`. Never treat an old theorem result or the snapshot's environment as permission to omit the changed source's enclosing declaration checking.
