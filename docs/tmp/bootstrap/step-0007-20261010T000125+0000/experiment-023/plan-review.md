## Scientific admission and bounded meaning

The selected RQ is unchanged: **How does prepared-state branching change end-to-end latency, throughput and memory at equal resources compared with established warm-session reuse?** The experiment tests an unresolved load-bearing part of this question: independent externally scheduled arrivals and resulting queue/latency/resource behavior. E020's closed-loop whole measurements cannot settle it, even where those measurements already show useful finite-lifetime gains or nearly neutral unlimited gains.

Success and failure produce different paper decisions. An advantage that survives both competent competitors can support a scoped service tradeoff. A branch loss or warm/snapshot match rules out this particular disposable policy as a general performance contribution. Lower memory with worse tails is explicitly mixed evidence. The expected overhead prediction is falsifiable, and the original failed/incomplete/operational candidates remain part of the denominator. This is not a tautological comparison, a compilation exercise or another GPU component probe.

The alternative E022 heterogeneous full capture is already independently admitted; duplicating it adds no evidence. E023 adds an independent service measurement that cannot be reconstructed from the old closed-loop clocks. Admitting it as a decisive formal-service experiment is reasonable, provided "decisive" means consequential evidence for the tested mechanism, not a complete answer to RQ3 or a settled paper contribution. The fixed-width load sweep leaves the explicit concurrency, placement, cancellation, preparation-depth and SMT promises open. Those remaining promises do not invalidate this admitted hypothesis and are not extra blockers for it.

The plan does not claim that fork, COW, snapshots, pruning, pooling or result caching are novel. Their substantial overlap with the closest-work map remains visible. No OSDI acceptance or novelty conclusion follows from winning this comparison alone.

## Baselines, native mechanism and fairness

Both competitors represent credible distinct answers within the existing baseline families. `prepared` retains the same prepared parent with unlimited native child streams, isolating the lifetime policy's cost without a cold-start strawman. `snapshot` independently executes the unchanged version-matched native full-snapshot stream with completed-success caching. Citation alone cannot supply their matched numeric behavior on these exact real candidate bodies at the declared offered rates.

Static source inspection confirms the intended distinctions. Branch passes `warm-stream ... 1`; prepared omits the optional retirement and therefore retains unlimited child streams; snapshot invokes the original `full` stream. The actual Lean seeded and stock stream cores use the same normal incremental frontend, unchanged checked command construction and original fallback for mismatched headers. The branch parent prepares only the first actually received header; later headers are not inspected for free and use the existing private source-native path. The proposed policy also loses cross-candidate private snapshot reuse when it disposes a child. This is a material part of the lifetime comparison, not evidence that merely changing a process count establishes a new algorithm.

All three methods use the same source order, equal native worker opportunities, CPUs0–3, default native threads, dispatch allowance, finite pending FIFO and completed-success-only exact(header,code) cache. Lookup happens at dispatch; there is no in-flight coalescing or rejected/incomplete caching. Actual cache hit counts can differ because different completion orders change when a success becomes available. That is disclosed service behavior under the same policy, rather than free oracle information. A result must retain those counts and cannot explain every difference as preparation sharing alone.

The proof width4 and mini width1 are matched across methods. Affinity is permitted capacity, not CPU/host isolation; the plan makes no memory quota or exclusive-host claim. Shared-host competition and non-atomic PSS sampling constrain causal precision. Mini's known heavy-worker dependency must be respected at actual launch; this review does not authorize a competing heavy mini process or stopping another owner.
