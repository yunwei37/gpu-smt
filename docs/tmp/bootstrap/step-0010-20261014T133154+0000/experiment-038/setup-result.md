## Build differences and unqualified boundaries

Experimental C++ headers are official LLVM libc++19.1.7 paired with ABI19 SDK libraries originally built with19.1.2; host glibc headers and runtime are used consistently. These are not a matched rebuild versus the shipped baseline. No causal performance benefit is claimed. Native build commands, failures and actual loaded maps are saved.

Unresolved in-flight prepared thunks, arbitrary native globals, external objects/OS effects, unsupported-effect admission/fallback and matched memory/timeout/cancellation policies remain unqualified. One successful arithmetic source and awaited descendant do not resolve them. No full29,750-source collector is launched, no original failures are filtered out, and no GPU is allocated for this CPU service mechanism.

The next consequential boundary is a useful supported native service regime and complete-cost/resource comparison against the strongest actual warm service, with a matched build/control where necessary. Ordinary concurrency and compiler optimization are not a new paper claim. If this mechanism's actual support or costs do not justify that comparison, record the limitation and close the constructor; the full Lean acceleration/research goal remains.
