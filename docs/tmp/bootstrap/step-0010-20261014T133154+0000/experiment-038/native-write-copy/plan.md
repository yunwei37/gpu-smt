# E038 implementation detail: defer prepared-ref copy until mutation

RQ3 and the full E038 native service hypothesis remain unchanged. The current implementation clones prepared refs on first access, contrary to the planned read-base-until-first-write mechanism. Root implements that missing distinction; the frozen-v1 full capture and its executable paths stay untouched. This is implementation/dependency work within E038, not a new paper experiment or another GPU kernel.

Split the native get hook from destructive take/set/swap. An unseen prepared ref read retains the original identity and reads the shared base. The first mutation obtains the native owned value, creates one MT branch cell, and publishes it under the context mutex. All later accesses resolve that cell. Branch-created refs retain the existing local-owner fast path. A read cache cannot keep an unowned raw address: the context retains every observed original until admitted work drains. A per-context write-generation invalidates cached base-read resolutions after a first private write, including writes by another admitted task. Distinct contexts never share versions.

The existing source-native builder creates a separate new artifact. Run the actual producer client with unchanged original accepted/rejected sources and a proportionate read/write witness, retaining raw source/commands/outcomes/EOF. These checks establish implementation engagement only, never performance or all-source equivalence. Record actual read-only refs and copied refs separately; no speedup may be inferred from their counts. Fresh independent source/lifetime/native-boundary review precedes publication.

No new full collector, matrix, model change, resource policy, writer replacement or canonical OMP-file edit is introduced. This change neither fills the missing defeq/argument wall-cost quantity nor admits the deferred GPU backend. A later numerical comparison needs the full matched regime and frozen final version, rather than pooling this setup with frozen-v1.
