## Proposed mechanism and competing explanation
At native Meta equality, discover corresponding independent argument pairs of
the same application head. Preserve native argument pass/assignment/synthesis
order: do not replace arbitrary stateful calls by unordered GPU unification.
Batch deterministic supported normalization/comparison over a retained immutable
expression/definition representation. Consume only positively established
equality answers when native execution reaches those pairs; every unsupported,
negative or unavailable case follows the original native method. Retain native
operand ownership through the batch and native continuation.
Reachable constant/universe/reduction support is necessary; merely feeding
old unsupported scalar beta packets to a wider launch does not complete this
implementation. No new daemon/service/scheduler or cross-process mutable Lean
state is introduced. Build private binaries; active SDK/REPLs remain intact.

Prediction: real independent work amortizes packing, transfers, device setup,
execution and readback in complete verification. Counterprediction: stock quick
equality/caches already consume cheap pairs, or the ready width/useful support is
too small, so GPU and/or batchedCPU lose. Both signs remain data.
