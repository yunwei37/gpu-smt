## Verified closest mechanisms

**KLEE, OSDI2008.** [USENIX proceedings](https://www.usenix.org/conference/osdi-08/klee-unassisted-and-automatic-generation-high-coverage-tests-complex-systems), [full primary text, section3.3](https://www.usenix.org/legacy/event/osdi08/tech/full_papers/cadar/cadar_html/paper.html). It already caches query outcomes and assignments, uses constraint subset/superset relations and tests cached assignments against new queries. It separates independence and caching in matched-work ablations. Thus exact caching or cheap validation of reused solver evidence is established. Its benchmark numbers are not transferred to Lean; only the measurement pattern is reusable, not its historical five-minute runtime setting.

**Green,2012.** [Author-indexed abstract](https://cs.sun.ac.za/~jaco/PAPERS/index.html), [author-hosted PDF](https://www.cs.sun.ac.za/~jaco/PAPERS/vgd12.pdf), [official artifact](https://github.com/GreenSolver/green). The primary abstract describes reuse across runs/programs/analyses/locations, and the artifact states simplification, canonicalization and shared persistence. Cross-request/cross-program storage or renamed query normalization therefore has high same-mechanism risk. The full author PDF fetch failed, so detailed evaluation claims are not made here. The available primary abstract/artifact suffice for this bounded overlap judgment.

**GreenTrie,2015 preprint.** [Primary arXiv abstract](https://arxiv.org/abs/1501.07174). This extends Green to implication-indexed constraint reuse with reduction/subset/superset queries. It prevents treating implication or semantic rather than exact matching as a fresh novelty merely because Lean is a new frontend. The record says submitted to ISSTA2015; this report does not assert acceptance.

**Mathlib linarith.** [Official frontend documentation](https://leanprover-community.github.io/mathlib4_docs/Mathlib/Tactic/Linarith/Frontend.html) and the actual pinned local Mathlib/Tactic/Linarith/Frontend.lean lines41-49,98-110. An untrusted replaceable oracle proposes coefficients; Lean reconstructs a proof through normalization rather than trusting that oracle. Therefore “untrusted accelerator plus Lean certificate validation” is an existing architectural boundary, not by itself the system contribution. This source supports a possible integration point, not useful GPU cost or cache compatibility for every trace record. Identical numeric LP records alone do not bind comparison coefficients to the current Lean expressions/hypotheses; no certificate conversion or compatibility is assumed.

## Baseline and experiment handoff

The competing position is that ordinary solver caching and proof-certificate reconstruction already capture this reuse, while the observed direct exact-query opportunity is too narrow to justify a new headline. If a generic cache matches/wins, a new name or a GPU wrapper cannot rescue novelty.

KLEE/Green/GreenTrie are citation-only precedents here, not additional numerical Lean baselines. Their official artifacts do not constitute a tested drop-in Lean certificate adapter, and no reproduction/runnable claim is made. Reusable experimental precedent: matched original work and separate component ablations from KLEE.
