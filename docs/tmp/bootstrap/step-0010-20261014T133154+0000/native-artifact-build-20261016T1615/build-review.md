## Findings in the initial source

1. **Nested UV object output directories are not created** (initial lines 104-119). The authoritative Lean4.27 runtime/CMakeLists.txt contains uv/net_addr.cpp, uv/event_loop.cpp, uv/timer.cpp, uv/tcp.cpp, uv/udp.cpp, uv/dns.cpp, uv/system.cpp and uv/signal.cpp. The script preserves those paths in plain-objects/uv/name.cpp.o but creates only plain-objects and private-objects. Clang cannot create the missing uv directory. Minimal repair: create each object's parent before invoking the compiler (including replacement parents if a future changed source has a subdirectory).

2. **The existing Lake trace format does not match the parser** (165-167). The actual retained matching GC REPL .lake/build/bin/repl.trace message starts ".> /tmp/.../lean-4.27.0-linux/bin/clang -o ...", not "cc ". The proposed next(...startswith("cc ")) therefore raises StopIteration even for the intended known input. The earlier executed recipe parsed the command after Lake's three-character ".> " prefix. Minimal repair: recognize the actual Lake trace command, then shlex parse the executable/arguments; preserve the actual source command in provenance. No separate compatibility layer or new trace file format is necessary.

3. **Backend initialization is hard-coded despite source-path-derived naming** (146-161). The script compiles implementation/NativeBranchBackend.lean with cwd=out and later calls initialize_NativeBranchBackend. The historical generated C really defines initialize_batch_x2dfrozen_x2dv1_NativeBranchBackend because its source was under that directory relative to the build cwd; the retained relink.executed.py fixed the initial hard-coded-name failure. The new implementation subdirectory changes module naming again. Minimal repair: discover the actual generated initializer from the generated C and substitute it, or explicitly set a correct root/cwd so the intended name is generated. The entry function gpu_smt_native_backend is an explicit exported name and does not need speculative renaming.

4. **A clean source tar lacks the generated githash header used by shell.cpp** (129-130, source include list 96-98). Official source util/shell.cpp includes "githash.h" at its line 53. The earlier private source preparation generated this header from the exact SDK commit; that historical preparation is absent from this new entry. Minimal repair: generate the header inside the new output include directory using the matching SDK's actual reported githash and include that directory for shell compilation. Do not mutate the pristine source input or invent a hard-coded commit. This is generated build input discovery, not a checksum/startup acceptance gate.

5. **A fresh output can still be nested inside an input tree** (40-54,62-63). exist_ok=False correctly refuses an already-existing output directory, including the known frozen roots. It does not stop a new child output under source/src, which copytree then recursively copies into its own destination, or a new child under another input tree that should remain an input. Minimal repair: before mkdir, reject an output resolved inside the supplied source/SDK/REPL/header/mimalloc trees. Independent output selection by the actual invocation remains required; the script need not add a catalog of historical frozen paths. It should not claim universal protection of arbitrary external directories from every possible caller-chosen descendant path.
