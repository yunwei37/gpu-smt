## Source-grounded scientific verdict before author-intent audit

Reject for OSDI; route EXPERIMENT_GATE. Confidence high that this version is not submission complete, moderate about whether a successful ambitious mechanism remains attainable. It is incomplete but promising as an investigation, not established simple-but-deep research. The simple principle is intelligible: preserve expensive preparation while separating native candidate history/lifetime. But established services already implement major parts of it, and this paper supplies neither a verified new mechanism nor an evidence-backed operating range that changes expert beliefs.

Strongest reject argument: the proposed advance beyond competent warm/snapshot reuse remains a promise while its decisive completed direct tests lose. Axle already combines preloading and independent request processes; Kimina/Snapshot-DSP already exploit preparation. Here ProofNet disposable branches have worse tail latency at every tested offered load, SMT branches take 28.84–37.91% longer with no sampled memory compensation, and GPU execution takes 1.58–3.64% longer for extremely little supported work. All four load-bearing RQs are explicitly unanswered. The positive CPU pairs do not validate the proposed native-branch principle. This conclusion follows the paper and verified sources, independently of later author logs.

The real tradeoff is not a strawman: Z3 API history sensitivity, fork runtime constraints, and Axle's isolation/throughput discussion establish it. What is not established is that this design resolves it better than existing systems. Strongest alternative explanation remains that the competent baseline already captures preparation, and per-attempt recreation pays overhead on a short residual path; CPU compilation/arithmetic implementation improvements explain favorable observations.
