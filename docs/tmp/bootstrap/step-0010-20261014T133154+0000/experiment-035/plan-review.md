## Measurement validity and intended inference

The source-native sites are a sound improvement. The actual first pass skips eligible propositions and postpones implicit/higher-order work; later passes synthesize instances and use different infer-type configurations. Hooking the six reached comparison sites at lines 274, 277, 296, 308, 315 and 318 can describe paid calls after these parent decisions. Preserving the real MetaM ABI, native state, order and return value is essential. Closed operands alone do not prove batch independence or expensive reduction; nested native calls can still use environment/configuration/caches.

The following are scientific requirements **if this diagnostic becomes necessary inside a later admitted experiment**, not a request to implement them now:

1. **Use one coverage population for numerator and denominator.** Unioned eligible child intervals must be inside the same recorded outer-defeq intervals, or the analysis must explicitly intersect them and report uncovered child work separately. Recompiling this object can observe same-object child calls that E033's export wrapper misses. “Same observer” does not by itself establish containment. Record static/DSO observation scope; missing paths restrict both the ratio and any negative closure. A small observed share cannot close unobserved paths or all closed-argument offload.
2. **Resolve pointer versus structural difference before measuring.** E034 uses Lean `a != b` in its collector, whereas E033 uses pointer identity. The plan currently leaves two different hypotheses open. Pointer inequality is a cheap broader opportunity descriptor, not E034 membership. Structural checks must not silently replace native work avoidance or be called free. Pick the claim, retain the other distinction honestly where available, and charge any additional work. No expensive all-call traversal is required merely for completeness.
3. **Make timing perturbation part of interpretability.** E033's real preflight was 23.11s versus 81.12s; this is not a causal overhead estimate, but it rules out assuming negligible perturbation. Timing many child calls can change their apparent share, cache/allocation behavior and 300s outcomes. State exactly whether classification, clock calls and nested observers enter each interval. An instrumented CPU ratio cannot establish the claimed low native-cost closure unless observation bias is bounded for that inference; otherwise it remains an observed-condition descriptor. A full extra benchmark matrix is unnecessary.
4. **Keep nesting, phase and censoring explicit.** Unioning nesting avoids arithmetic double counting but does not prove independent ready work; record all six source phases rather than merging changed configurations. Entered/completed/censored counters are good. Completed numerator over completed outer denominator requires consistent handling of terminated parents and completed descendants; do not silently keep one side and drop the other. Missing/init/clock failures cannot be treated as zero opportunity.

The proposal correctly refuses to multiply the ratio by E032's separate 35%, infer GPU gain from counts, or call process clocks exhaustive tree CPU. Those limits should remain. The primary ratio is a project diagnostic quantity built from standard thread CPU semantics, not a published standard RQ4 performance metric. This is acceptable for an internal selector if defined precisely. Paper-facing claims still require complete wall latency/throughput/resource boundaries and the relevant strongest CPU path. Add the actual official clock documentation link when reporting timing; its absence now is a documentation repair, not the reason for rejection.
