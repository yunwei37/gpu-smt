## Must-fix

1. **Make the original executable oracle actually consume original stream bytes.** The executable currently receives `inputs/N.full`, reconstructed through `split_commands`, just as the API variants do. Consequently a shared parser omission or rewriting error can produce four-way agreement while the original captured stream behaves differently. This does not test the declared preservation of original native responses. Send `Path(job['trace']).read_text()` to the CLI, retain/hash the original input alongside the generated API full/prefix/suffix inputs, and explicitly record that splitting reconstructs commands rather than preserving byte identity. Alternatively retain a separately qualified original-byte oracle and compare the reconstructed CLI to it. This is a necessary oracle qualification, not a new baseline. No need to invent a new parser or control interface.

2. **Enforce complete response coverage and terminal error accounting in the outcome interpretation.** The current equality test accepts two equally incomplete response lists, including empty lists, as agreement. `missing_streams` only detects absent output files; neither a short output nor a nonzero process/child status enters that list. Raw process statuses are available, including child wait statuses in parent stdout, which makes repair straightforward. Record the expected checks per source stream (440 total), require exactly that many ordered decision responses for a successful comparison, and keep API errors/nonzero parent or child exits separately visible as failures or invalid/inconclusive comparisons. CLI repetitions must each meet this condition rather than inheriting a short first-pass oracle through `setdefault`. An error with a complete matching decision sequence may be reported as decision parity plus execution failure; it must not silently qualify the driver/boundary. These conditions already follow the plan's promise that missing responses and errors remain failures. Fixed post-run recomputation can implement them if documented before execution; a new gate/schema is unnecessary.
