## Must-fix findings

1. **Interpretation / namespace confounding.** A broad statement that real related candidates have no shareable native preparation would overclaim this evidence. Unique candidate_INDEX identifiers occur in 8,367 of the 8,370 sampled prefixes. The source-copy protocol deliberately generates different native crate names even for identical source bytes. This is a competing explanation for zero literal recurrence, not evidence that proof-body changes eliminate every reusable state. **Concrete fix suggestion:** state “zero exact first-flush input recurrence under unique candidate filenames and fixed literal identity,” explicitly including zero exact-source duplicate hits and the namespace occurrence count. Do not describe this as a semantic reuse test, cache impossibility, general SMT limit, or all-RQ1 answer. This limits inference without invalidating the declared literal-protocol measurement; do not silently normalize symbols to manufacture a positive result.

2. **Correctness table / native success meaning.** Counting JSON success=true as acceptance would produce 609 successes per repeat instead of 190 exit-zero jobs. Official main.rs computes success from verifier VIR/error counters before separately honoring driver status; compile/type failures can leave verified=0/errors=0 and success=true while returning 1. **Concrete fix suggestion:** report exit, JSON success, verified count and diagnostics separately; use 190 exit-zero terminal source jobs only with its declared meaning, retain the 419 exit-one/verified-zero rows, and avoid any task-intent or soundness certification.

3. **Correctness coverage / missing JSON.** Full transparency cannot be claimed for all 10,698 pairs. Seventeen inputs × three repeats have exit 101 and no stdout JSON. **Concrete fix suggestion:** put 10,647 equal / 0 different / 51 unknown beside every feedback-equality claim, preserve their source identities and abnormal status, and say observed comparable feedback rather than all-corpus correctness equivalence.

## Should-fix findings

1. **Preparation CPU / quantization.** Median process CPU zero is not zero initialization; two independently quantized user/system fields can both truncate below a tick. Live schedstat supplies a separate approximately 15 ms active-task observation, excludes departed tasks and samples after marker arrival. **Concrete fix suggestion:** show both observations with their distinct coverage and time resolution. Do not replace process lifetime CPU with schedstat, interpret the symmetric tick interval as a statistical confidence interval, or divide schedstat by quantized process ticks to derive a saving.

2. **Cost / observer attribution.** Matching feedback does not make timing unobtrusive. Python startup, three stream threads, trace writes, snapshot I/O and holding DONE add resource cost; condition blocks and host load also permit drift. **Concrete fix suggestion:** retain paired repeat totals and the 10.59% wall/11.18% reported CPU overhead, label snapshot costs captured-condition observations, and do not subtract aggregate overhead to invent direct initialization CPU. Three repeats establish descriptive stability, not an independent-input confidence interval or host-isolated causal decomposition.

3. **Timing definitions / non-partition.** Native smt-init begins after the first statistics flush and includes subsequent query/version handling; module aggregates omit function buckets and integer milliseconds truncate. Estimated-cpu-time with one thread is elapsed time by source definition. **Concrete fix suggestion:** keep these as diagnostics, never use smt-init to represent this first-flush boundary, never add nested VIR/Rust/native elapsed scopes as CPU, and never present lifetime solver cost as preparation cost.

4. **Coverage / workload leakage.** Saved finals/intermediates, duplicate sources and log stages are authentic but not original arrival/native-call order. Ideal prior retention and lexicographic order do not model bounded multi-project traffic. The 2,790 solver calls arise from 2,789 solver-engaging inputs per repeat, distinct from all 3,566 whole-source jobs. **Concrete fix suggestion:** preserve both denominators and original context identities in the paper table; label all-source costs versus eligible solver samples, and do not extrapolate to hidden generation/Houdini calls or independent systems workloads.
