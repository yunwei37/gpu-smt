# 0.1.0 release notes — prepared, not published

ProofServe provides a Kimina-compatible Lean verification service, a Rust
extension API and a minimal Python batch client. This is an experimental first
release; its public APIs may change before 1.0.

Current qualification: source packaging and ordinary native CI pass. Full
Mathlib container qualification remains open; the latest entrypoint correction
has not received another complete image build. Publication is not part of this
preparation. The measured failures and correction are recorded below.

## Included

- `proofserve-core`, `proofserve-engine`, `proofserve-lean` and `proofserve` crates.
- The `proofserve` HTTP/JSONL CLI with automatic CPU and memory detection.
- A Docker recipe with pinned Lean 4.18.0, Mathlib and REPL revisions.
- A dependency-free Python client and batch example.
- Exact candidate reuse, joint resource admission and separate all-candidate
  and first-success modes.

## Measurement

The retained 7,808-source pair returns the same final statuses and 3,014 accepted
IDs. ProofServe takes 20,323.01 s versus 25,176.49 s for four warm Kimina REPLs:
1.24× at that point. See the [benchmark protocol](../../bench/lean-warm-resource/README.md)
for retry-order, CPU-eligibility and raw-response differences. This is not an
isolated COW gain or a performance guarantee for other workloads.

### Corrective qualification plan

Proof acceptance/error/sorry assertions remain enforced; HTTP transport has a separate 240-second deadline.
