## Resource adaptation and lifecycle

Four native workers share CPUs8–11 and48GiB sampled actual owned RSS.
A benchmark-local Repl constructor sets its existing max_memory_bytes field to
RLIM_INFINITY, so the existing preexec sets unlimited RLIMIT_AS. Installed
Kimina source and its default settings are unchanged. The exact field adaptation
must be recorded; this is not a claim of completely unmodified baseline code.
Qualification requires actual /proc address-limit observations and four live
REPLs, rather than trusting configuration labels.

The retained owned-tree watchdog samples each second, attributes/kills the
largest own REPL and records its source. Admission stops on actual pressure.
After an actual concurrent preemption, peers finish, all idle warm workers retire,
and the preempted original source executes exclusively under the same48GiB
budget. A solo excess is a resource failure. Source forecasts never reject.
These resource-control rules differ from historical24GiB-AS timings.

Official asynchronous close operations are retained and awaited once per native
Process object. This is benchmark retirement glue; no proof search/reuse algorithm
changes. Dynamic admission/watchdog, queue/drain, warmup, retries and cleanup count.
RSS sampling can overshoot and is not a kernel-hard quota.
